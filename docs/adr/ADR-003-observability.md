# ADR-003: Observability via structlog and LangSmith

## Status

Accepted — 2026-06-07

## Context

An enterprise AI system must produce **structured, queryable logs** and
**distributed traces** that map cleanly onto subgraph boundaries. The
default `logging` module emits unstructured text, and LangSmith
requires explicit environment wiring.

## Decision

We adopt:

* **`structlog`** for application-level logging. The first call to
  `configure_logging` is the only effective call; subsequent calls
  are no-ops so that tests can invoke it freely. Output is JSON to
  stdout.
* **LangSmith** (`LANGCHAIN_TRACING_V2=true`) is enabled via
  environment variables. `observability.tracing.configure_langsmith`
  reads them and applies them via `os.environ` so that LangChain's
  internals pick them up.
* **Per-subgraph timings** are recorded into
  `metadata["subgraph_timings"]` by each node using a small
  `time.perf_counter()` wrapper.
* **Request and trace IDs** are generated by
  `generate_request_id` / `generate_trace_id` (UUIDv4) and stored on
  the `GraphState` for end-to-end correlation.

## Consequences

### Positive

* All logs are JSON — easy to ship to ELK, Loki, or Cloud Logging.
* LangSmith provides visual trace inspection with no extra code in
  the application.
* Request IDs flow through the entire pipeline, enabling per-request
  log filtering.

### Negative

* `structlog`'s `BoundLogger` is typed as `Any`; we accept this to
  avoid the maintenance burden of typing every structlog call site.
* LangSmith adds an outbound network call when enabled; tests must
  keep `LANGCHAIN_TRACING_V2=false` to remain hermetic.
